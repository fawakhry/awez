# دليل نشر منصة عاوز والتحقق منها

هذا الدليل يحدد خطوات موحدة للتحقق من أن نسخة `main` وصلت فعلًا إلى GitHub Pages، وكيفية الرجوع بسرعة إذا ظهر خلل بعد النشر.

## رابط النسخة المنشورة

- المنصة: https://fawakhry.github.io/awez/
- Workflow النشر: `.github/workflows/deploy-pages.yml`
- بيئة النشر: `github-pages`

## قبل الدمج

1. تأكد أن اختبارات Pull Request كلها ناجحة.
2. راجع أن التغيير لا يحتوي أسرارًا أو إعدادات دفع حقيقية أو خدمة مدفوعة غير مقصودة.
3. تأكد أن التغيير محدود النطاق ولا يكرر تحسينًا موجودًا على `main`.

## بعد الدمج

1. افتح تشغيل GitHub Actions المرتبط بآخر commit على `main`.
2. تأكد أن job الاختبارات نجح قبل job النشر.
3. انتظر حتى تصبح خطوة `Deploy` ناجحة؛ نجاح الدمج وحده لا يعني أن GitHub Pages أنهى النشر.
4. افتح رابط المنصة في نافذة خاصة أو بعد تحديث قوي لتجنب نسخة Cache قديمة.
5. نفّذ فحصًا سريعًا للوظائف الأساسية:
   - فتح الصفحة الرئيسية والبحث.
   - فتح متجر وإضافة منتج للسلة.
   - فتح السلة والوصول إلى تأكيد الطلب بدون إرسال بيانات حقيقية.
   - فتح دخول التاجر والتأكد أن لوحة التاجر تظهر.
   - فتح جولة 360 والتأكد أن العارض يبدأ بدون خطأ.

## التحقق من النسخة المنشورة

GitHub يوفر Deployment history وواجهات REST لمعرفة حالة GitHub Pages. عند الشك في أن آخر commit لم يصل بعد، قارن commit الذي شغّل workflow مع آخر deployment ناجح بدل الاعتماد على وقت الدمج فقط.

مراجع GitHub الرسمية:
- https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages
- https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/control-deployments
- https://docs.github.com/en/rest/pages/pages

## الرجوع عند ظهور مشكلة

1. لا تعدّل بيانات أو إعدادات حساسة لمحاولة إصلاح المشكلة مباشرة على الإنتاج.
2. حدّد أول commit تسبب في المشكلة من سجل `main` وGitHub Actions.
3. أنشئ Pull Request صغيرًا يعكس التغيير المسبب فقط، أو أصلح السبب في فرع منفصل.
4. شغّل نفس الاختبارات قبل الدمج.
5. بعد الدمج، كرر فحص ما بعد النشر أعلاه وتأكد أن GitHub Pages نشر commit الإصلاح.

## متى لا يتم الدمج تلقائيًا

لا يتم الدمج التلقائي إذا فشلت الاختبارات، أو كان التغيير كاسرًا، أو احتاج قرارًا تجاريًا، أو مس بيانات حساسة/دفعًا حقيقيًا، أو كان أثره غير واضح.

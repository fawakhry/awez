# عاوز — النسخة التجريبية v0.2

نسخة تشغيلية أولية لتجربة مشروع **عاوز** في بنها: العميل يبحث ويطلب، والتاجر يدير المنتجات والطلبات من نفس نموذج الويب.

## رابط النسخة المنشورة

`https://fawakhry.github.io/awez/`

## تشغيل نسخة الويب محليًا

تحتاج Python 3 فقط. من جذر المستودع شغّل:

```bash
python -m http.server 8000 --bind 127.0.0.1 --directory prototype
```

ثم افتح `http://127.0.0.1:8000/` في المتصفح.

> هذا الخادم مناسب للتطوير المحلي فقط، وليس خادم إنتاج.

## كيف تُبنى نسخة GitHub Pages

ملف `prototype/index.html` في المستودع هو **المصدر الخام** وليس نسخة مطابقة حرفيًا لما يصل إلى GitHub Pages. أثناء النشر، يقوم `.github/workflows/deploy-pages.yml` بتجهيز الصفحة قبل رفعها، ومن ذلك:

- حقن ملفات JavaScript الخاصة بتحسينات البحث، الطلبات، لوحة التاجر، الوصولية والعمل دون اتصال قبل `</body>`.
- إضافة ملفات CSS والـWeb App Manifest وسياسة `referrer` داخل `<head>`.
- إزالة أصول Pannellum القديمة قبل نشر النسخة النهائية.

لذلك عند التحقق من أن تحسين Runtime يصل إلى الإنتاج، راجع **مسار النشر والاختبارات المرتبطة به** ولا تعتمد على وجود `<script>` له داخل `prototype/index.html` الخام وحده. وبالمثل، فتح الملف الخام أو تشغيله محليًا لا يثبت تلقائيًا أن كل تحسين يُحقن وقت النشر موجود في الصفحة المحلية.

إذا أضفت Runtime جديدًا يجب أن تحدد بوضوح هل سيُحمّل من `index.html` نفسه أم سيُحقن عبر `deploy-pages.yml`، وأن تضيف له اختبارًا مناسبًا لمسار النشر حتى لا يصبح الملف مختبَرًا لكنه غير منشور.

## تشغيل الاختبارات

من جذر المستودع شغّل نفس الأمر المستخدم في GitHub Actions:

```bash
node --test --test-concurrency=1
```

يشغّل Node.js تلقائيًا ملفات الاختبار المطابقة للأنماط القياسية، ومنها ملفات `*.test.cjs` الموجودة داخل `tests/`. ولتشغيل اختبار واحد أثناء التطوير يمكن تمرير مساره مباشرة، مثل:

```bash
node --test tests/search-landmark.test.cjs
```

## المحتويات

- `prototype/index.html`: تطبيق ويب تفاعلي يعمل على الموبايل والكمبيوتر.
- `android/`: مشروع Android Native بـ Kotlin وJetpack Compose.
- `backend/`: API أولي بـ FastAPI للبحث والطلبات.

## وظائف نسخة الويب v0.2

### العميل

- بحث كتابي وصوتي بالعربية.
- نتائج أنشطة تجريبية في بنها.
- صفحة متجر ومنتجات ومخزون.
- سلة متعددة المنتجات مع تعديل الكميات.
- فاتورة بالجنيه المصري.
- نموذج عنوان وبيانات العميل وطريقة الدفع عند الاستلام.
- إنشاء طلب برقم مرجعي ومتابعة حالته من صفحة «طلباتي».
- جولة 360 ونقاط تفاعلية تضيف المنتجات إلى السلة.

### التاجر

- تسجيل دخول تجريبي.
- لوحة مؤشرات للمنتجات والطلبات والمبيعات المسلّمة.
- إضافة وتعديل وحذف المنتجات.
- التحكم في السعر والمخزون وحالة توفر المنتج.
- مشاهدة بيانات الطلب وتغيير حالته: جديد، جاري التجهيز، في الطريق، تم التسليم، أو ملغي.

## بيانات دخول التاجر التجريبية

- اسم المستخدم: `merchant`
- كلمة المرور: `1234`

> بيانات نسخة الويب محفوظة داخل `localStorage` على نفس المتصفح. تسجيل الدخول الحالي تجريبي وليس نظام حماية إنتاجيًا.

## تشغيل تطبيق أندرويد

1. افتح مجلد `android` في Android Studio حديث.
2. نفّذ Gradle Sync.
3. شغّل التطبيق على هاتف أو Emulator بنظام Android 8 فأحدث.
4. وافق على إذن الميكروفون عند استخدام البحث الصوتي.

## تشغيل الـ Backend

```bash
cd backend
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate
pip install -r requirements.txt
fastapi dev main.py
```

توثيق الـ API يظهر في: `http://127.0.0.1:8000/docs`
